# 01 需求、范围与成功标准

## 用户与目标

用户是需要查询企业制度或产品 FAQ 的员工。一次输入是自然语言问题及可选对话上下文；资料是带文档 ID、版本日期和适用范围的合成制度。输出包含答案或明确的未完成原因、引用的文档 ID 与原文片段、资料缺口和执行 Trace。

## 本次范围

实现 CLI、合成资料检索、原文读取、冲突核对、模型驱动的工具循环、证据校验、自动测试和运行记录。只用合成数据；不处理真实公司机密。优先让“正常回答／冲突／资料不足／工具失败／相似问题”可复现。

## 可验收成功标准

| 场景 | 预期 |
| --- | --- |
| 普通事假 | 回答“至少提前 2 个工作日”，附 L01 原句 |
| 一般费用报销 | D01 与 D02 冲突时列出两方原文并追问优先级，不擅自选 15 天 |
| 差旅费用 | 使用 D03 的返程后 10 个自然日，不误用一般费用期限 |
| 远程办公天数 | 明确资料未规定天数，指出待补资料 |
| 工具失败 | 返回工具故障，不伪装成确定答案 |
| 执行上限 | 返回 `incomplete` 和原因 |
| 伪造引文 | 拒绝终结，要求模型修正或到上限停止 |
| 上下文追问 | 根据前轮“普通事假”理解“那紧急情况呢？”，读取 L01 的紧急情况条款并给出引用 |

真实模型成功标准还包括：至少两种问题形成不同工具路径，Trace 能显示模型基于工具观察调整动作；实际结果记录在评估文档。Mock 仅验证程序流程。

## 非目标

网页、生产部署、多 Agent、实时知识库管理、权限系统、向量数据库及真实企业资料接入不在这次核心链路内。当前资料规模不需要大型检索框架。
